# Firestore Security Rules Specification

## Data Invariants
1. `ecosystems`: Indexed by normalized document key matching `^[a-zA-Z0-9_\\-]+$`. Any user or doctor can read and write their ecosystem record.
2. `doctors`: Individual doctor profile indexed by doctor ID (`^[a-zA-Z0-9_\\-]+$`).
3. `settings/payment_config`: System payment settings. Reads are open for all users so billing details load. Writes allowed for authenticated users/admins.
4. `documents`: Medical documents generated by doctors. Read and write allowed for document creation/sharing.

## The Dirty Dozen Test Payloads
1. Payload with 1MB ID string (ID Poisoning attack) -> PERMISSION_DENIED.
2. Payload with illegal characters in document ID -> PERMISSION_DENIED.
3. Ecosystem write with non-string `identifier` -> PERMISSION_DENIED.
4. Ecosystem write with invalid `updatedAt` field type -> PERMISSION_DENIED.
5. Doctor profile write with oversized `doctorName` (>500 chars) -> PERMISSION_DENIED.
6. Doctor profile write with oversized `id` (>128 chars) -> PERMISSION_DENIED.
7. Document record with missing required field `patientName` -> PERMISSION_DENIED.
8. Unauthenticated list query attempting blanket read on root -> PERMISSION_DENIED.
9. Payment config update with string `tasaBinanceUsd` instead of number -> PERMISSION_DENIED.
10. Ecosystem update trying to remove `identifier` required field -> PERMISSION_DENIED.
11. Document write with `date` set to 100KB string -> PERMISSION_DENIED.
12. Random undefined collection access -> PERMISSION_DENIED (catch-all rule).

## Security Rules Strategy
- Catch-all default deny for any unknown collection path.
- `isValidId(id)` helper guarding all doc IDs (`id is string && id.size() <= 128 && id.matches('^[a-zA-Z0-9_\\-]+$')`).
- Type and size checks on all core properties.
